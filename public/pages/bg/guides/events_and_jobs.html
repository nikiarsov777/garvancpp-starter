Events & Jobs — стъпка по стъпка

Това ръководство те води от една HTTP заявка до реален HTML email в inbox-а ти. Минава през всеки слой на event / job pipeline-a в starter-a — event dispatcher, listener chain, job dispatcher, sync driver и libcurl SMTP транспорт.

Пълният поток

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(AppEvents::UserRegistered)
      → LogRegistrationListener::handle()      (пише log ред)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline в този HTTP thread)
                     → SendTestMail::handle()  (libcurl SMTP send)

Нищо не се queue-ва в background worker в Phase A — всеки step тече в request thread-а и HTTP response-ът се връща едва след като mail-ът е предаден на SMTP сървъра. Т.е.: ако получиш HTTP 200, mail-ът е приет от mail сървъра; ако е отхвърлен, request-ът приключва с грешката в лога.

Тригериране с curl

С работещ ./bin/app.bin и настроени MAIL_* (виж Mail (SMTP)):

curl "http://localhost:9090/api/events/user-registered?email=you@x.com&name=You&id=1"

Очакван response:

{
  "status": "fired",
  "event": "UserRegistered",
  "listeners": 2,
  "payload": {"user_id": 1, "email": "you@x.com", "name": "You"}
}

Четене на server log-а

В терминала, където върви ./bin/app.bin, трябва да видиш по ред:

[LogRegistrationListener] user #1 You <you@x.com> registered
[SendTestMail] dispatch driver=smtp host=smtp.example.com:465 enc=tls from=<...> -> to=<you@x.com> subject="Welcome ..." body_len=...
[SendTestMail] SMTP send OK via smtps://smtp.example.com:465 -> <you@x.com>
(YYYY-MM-DD HH:MM:SS) [INFO    ] Response: ... /api/events/user-registered?... 200 0

Ако вместо това видиш SMTP send FAILED, последният ред съдържа libcurl error string-a — това е actionable съобщението.

Отстраняване на проблеми

  • 404 HTML вместо JSON — работещият binary няма регистрирани routes. Rebuild с ./make.sh и рестарт.
  • 404 JSON "no factory for '...'" — името на job-а или event-a в URL / payload не съвпада с регистриран запис. Ползвай ./kalpasan job:list и ./kalpasan event:list, за да видиш какво е bound; провери app/providers/JobServiceProvider.cpp и EventServiceProvider.cpp.
  • SMTP send OK но mail не пристига — първо spam folder-a. Ако е празен, включи CURLOPT_VERBOSE=1L в app/jobs/SendTestMail.cpp, rebuild, retry и прочети целия SMTP dialog (детайли).
  • Тих hang — вероятно SMTP сървърът не отговаря. Пробвай openssl s_client -connect <host>:465 от същата машина; ако не работи, мрежа / firewall.
  • SPF / DKIM проблеми — първо изпращане от нов domain към gmail.com, abv.bg и т.н. често отива в spam. Настрой SPF / DKIM / DMARC за твоя domain.
