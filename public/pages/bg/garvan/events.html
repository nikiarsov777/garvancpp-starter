Events

Events позволяват на една част от приложението да уведоми останалите, без да знае кой слуша. Fire-ваш event веднъж; всеки регистриран listener се изпълнява — синхронно, по реда на регистрация, в същия thread.

Event API

Event-ът е малък value class, наследяващ Garvan::Event:

// app/events/UserRegistered.h
#include "events/Event.h"
#include "tools/JsonValue.h"

namespace AppEvents {

class UserRegistered : public Garvan::Event
{
public:
    UserRegistered() = default;
    UserRegistered(int id, std::string mail, std::string person)
        : user_id(id), email(std::move(mail)), name(std::move(person)) {}

    std::string eventName() const override { return "UserRegistered"; }

    Garvan::JsonValue payload() const override;
    static std::unique_ptr<Garvan::Event>
        fromPayload(const Garvan::JsonValue& p);

    int         user_id{};
    std::string email;
    std::string name;
};

} // namespace AppEvents

Писане на listener

Наследяваш Garvan::Listener<YourEvent> и имплементираш handle():

// app/listeners/SendWelcomeEmailListener.h
#include "events/Listener.h"
#include "../events/UserRegistered.h"

class SendWelcomeEmailListener
    : public Garvan::Listener<AppEvents::UserRegistered>
{
public:
    void handle(const AppEvents::UserRegistered& event) override;
};

Тялото на listener-a може да прави всичко — да пише в базата, да вика service или да dispatch-ва job (което точно SendWelcomeEmailListener прави, forward-вайки към AppJobs::SendTestMail).

Изстрелване на event-и

#include "events/EventDispatcher.h"
#include "app/events/UserRegistered.h"

Garvan::EventDispatcher::fire(
    std::make_unique<AppEvents::UserRegistered>(42, "u@x.com", "Ada"));

Listener-ите се викат синхронно в същия thread; ако някой хвърли, следващите пак се изпълняват, а fire() re-raise-ва първата exception в края.

Регистрация в service provider

Две регистрации в EventServiceProvider::register_():

// app/providers/EventServiceProvider.cpp
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                LogRegistrationListener>();
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                SendWelcomeEmailListener>();

// Optional: регистрира event factory-то за admin API `event:fire`
GARVAN_REGISTER_EVENT(AppEvents::UserRegistered);

За разлика от GARVAN_REGISTER_JOB, event макросът е ОК: dispatch ключът се взема от eventName() runtime, а не от stringified type name.

Provider-ите boot-ват в main.cpp:56-60 във фиксиран ред — AppServiceProvider първи (queue driver-и), после JobServiceProvider, накрая EventServiceProvider. Listener-ите могат безопасно да dispatch-ват jobs при boot, защото jobs вече са регистрирани.

Пример: UserRegistered chain

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(UserRegistered)
      → LogRegistrationListener::handle()      (sync log ред)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline)
                     → SendTestMail::handle()  (libcurl SMTP send)
