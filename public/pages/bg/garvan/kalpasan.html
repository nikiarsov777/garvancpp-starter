Kalpasan CLI

kalpasan е спътникът от командния ред на проекта. Скаффолдва модели, контролери и услуги, изпълнява миграции и seeder-и, и стартира development сървър с file watching.

Инсталация

Изпълнимият файл се намира в vendors/Garvan/kalpasan. Symlink в корена на проекта прави извикването му удобно:

ln -s vendors/Garvan/kalpasan kalpasan
./kalpasan --help

Скафолдинг и DB команди

./kalpasan make:model User           # скаффолдва app/models/User.{h,cpp}
./kalpasan make:controller User      # скаффолдва app/controllers/UserController.{h,cpp}
./kalpasan make:service User         # скаффолдва app/services/UserService.{h,cpp}
./kalpasan make:migration create_users

./kalpasan db:migrate                # делегира към garvan-migrate up
./kalpasan db:rollback               # делегира към garvan-migrate down
./kalpasan db:seed                   # изпълнява файловете в db/seeders/

./kalpasan serve --watch             # rebuild + рестарт при промяна на .cpp/.h

Всички команди уважават активния .env файл, така че работят срещу правилната база.

Runtime verbs (jobs, events, config)

Тези verbs говорят с работещото приложение по HTTP (libcurl). Четат KALPASAN_ADMIN_URL (default http://127.0.0.1:9090) и KALPASAN_ADMIN_TOKEN от .env, после хитват bearer-guarded admin endpoint-ите в routes/AdminRoute.cpp.

./kalpasan job:list                                # GET /api/admin/jobs
./kalpasan job:dispatch SendTestMail \              # POST /api/admin/jobs/dispatch
    --field to=you@x.com \
    --field subject="Hi" \
    --field body="<h1>Hello</h1>"

./kalpasan event:list                              # GET /api/admin/events
./kalpasan event:fire UserRegistered \             # POST /api/admin/events/fire
    --field id=42 \
    --field email=you@x.com \
    --field name="Ada"

./kalpasan route:list                              # изведи HTTP routes
./kalpasan config:show                             # dump .env
./kalpasan config:get MAIL_HOST                    # чети един ключ
./kalpasan config:set MAIL_HOST smtp.new.com       # пренапиши един ключ
./kalpasan config:key:generate                     # нов APP_KEY (base64 32-byte)
Admin auth guard

AdminRoute отказва заявката ако едно от три условия не е в сила: KALPASAN_ADMIN_TOKEN да е непразен в .env, заявката да идва от loopback (127.0.0.1 или ::1) и header-ът Authorization: Bearer <token> да съвпада. Иначе получаваш JSON error със статус 401 / 403 / 503 (виж routes/AdminRoute.cpp:55-82).
