Jobs

Jobs са единици фонова работа. Всеки job е C++ клас, наследяващ Garvan::Job. Може да се тригерира директно, от event listener или през admin HTTP API (което kalpasan job:dispatch прави вътрешно).

Job API

Override-ваш четири неща и предоставяш един static factory:

// app/jobs/MyJob.h
#include "queue/Job.h"
#include "tools/JsonValue.h"

namespace AppJobs {

class MyJob : public Garvan::Job
{
public:
    MyJob() = default;
    MyJob(std::string arg) : arg_(std::move(arg)) {}

    void handle() override;                                 // върши работата
    std::string jobName() const override { return "MyJob"; }
    std::string connection() const override { return "sync"; } // sync | async | database

    Garvan::JsonValue payload() const override;             // сериализира за persist queue-та
    static std::unique_ptr<Garvan::Job>
        fromPayload(const Garvan::JsonValue& p);            // обратното на payload()

private:
    std::string arg_;
};

} // namespace AppJobs

Регистрация на job

Регистрирай всеки user job в JobServiceProvider::register_(). Ползвай JobRegistry::bind() директно с short name-a от jobName():

// app/providers/JobServiceProvider.cpp
Garvan::JobRegistry::bind("MyJob", &AppJobs::MyJob::fromPayload);
Не ползвай GARVAN_REGISTER_JOB за user jobs

Макросът GARVAN_REGISTER_JOB(AppJobs::MyJob) stringify-ва целия token и регистрира ключа като "AppJobs::MyJob", което не съвпада с jobName() или short name-a, който kalpasan job:dispatch очаква. Виж fix-a в app/providers/JobServiceProvider.cpp:18.

Dispatch-ване

От където и да е в кода — controller, listener или друг job:

#include "queue/JobDispatcher.h"
#include "app/jobs/MyJob.h"

Garvan::JobDispatcher::dispatch(std::make_unique<AppJobs::MyJob>("hello"));

Dispatcher-ът рутира job-а към driver-а, посочен от job->connection(). Driver-ите се bind-ват от service provider-и; в starter-a в момента е окабелен само "sync".

SyncDriver

SyncDriver изпълнява job-а inline в извикващия thread. Това е default в Phase A и дава call-and-return семантика като обикновена функция — идеално за тестове, low-throughput задачи или pipeline-и тригерирани от HTTP request. Async и database-driver-ите ще влязат в същото JobDispatcher API в следващи фази без промени в job класовете ти.

Пример: SendTestMail

Вграденият AppJobs::SendTestMail (app/jobs/SendTestMail.h:21) е реален, изпращащ job. Неговият handle() отваря SMTP сесия с libcurl, праща HTML email използвайки MAIL_* блока от .env и логва резултата на stdout. Виж Mail (SMTP) за SMTP страната и Kalpasan CLI за job:dispatch verb-a.
