ORM / Query Builder

Слоят за данни на Garvan има две части. Builder генерира parameterized statement-и през Grammar за конкретната база и ги изпълнява през DbClient. OModel е базовият клас, който вашите модели наследяват, за да експонират builder методите директно.

Builder

Builder-ът използва fluent API. Всяко извикване връща builder-а, така че можете да верижите условия:

Builder qb(dbClient, grammar, "users",
           /*public*/{"id","name","email"},
           /*private*/{"password"});

auto rows = qb
    .where("active", "=", "1")
    ->where("role", "=", "admin")
    ->get();

Заявката е изцяло parameterized — стойностите от потребителя минават през native PreparedStatement binding, а не през конкатенация на низове. SQL injection не е на масата.

Други удобни методи: first(), firstOrFail(), find(id), findOrFail(id), плюс insert(json), update(json) и remove().

OModel

Моделите наследяват ORM::OModel и декларират име на таблица и списъци с колони:

class User : public ORM::OModel
{
public:
    User() {
        table          = "users";
        primaryKey     = "id";
        public_columns  = {"id", "name", "email"};
        private_columns = {"password"};
    }
};

Граматики за всяка база

Всеки драйвер предоставя Grammar subclass, който знае как да генерира правилния диалект:

  • PostgresGrammar
  • MysqlGrammar
  • SqliteGrammar
  • MonetdbGrammar
  • MongoGrammar — произвежда Mongo команди, а не SQL.

Правилната граматика се избира автоматично от DATABASE_TYPE. Обикновено не пипате тези класове директно.
