Миграции

Garvan доставя самостоятелен инструмент за миграции, наречен garvan-migrate. Той чете SQL или JSON файлове от db/migrations/, прилага ги в подреден по версия ред и записва какво вече е изпълнено в служебна таблица.

Изпълняване на миграции

./vendors/Garvan/garvan-migrate up        # прилагане на чакащи миграции
./vendors/Garvan/garvan-migrate down      # връщане на последната приложена миграция
./vendors/Garvan/garvan-migrate status    # показва какво чака / е приложено

Инструментът чете connection настройките си от същия .env файл, който приложението ви използва.

Писане на миграция

Имената на файловете следват <UTC YYYYMMDDhhmmss>_<описание>.sql. Всеки файл има две секции, маркирани в dbmate стил:

-- migrate:up
CREATE TABLE posts (
    id          serial PRIMARY KEY,
    title       text NOT NULL,
    body        text,
    user_id     integer REFERENCES users(id),
    created_at  timestamp DEFAULT now()
);

-- migrate:down
DROP TABLE posts;

За варианти за конкретна база добавете .<dbtype> преди .sql — например 20240501_create_posts.mysql.sql.

Връщане назад

Всяко up трябва да има съответстващо down — инструментът отказва да приложи миграция без него. garvan-migrate down ги изпълнява в обратен ред, една по една.

MongoDB

За MongoDB миграции тялото на файла е един или повече top-level JSON документа. Всеки от тях се изпраща към db.runCommand() поред.
