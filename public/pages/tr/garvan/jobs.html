Jobs

Jobs, arka plan iş birimleridir. Her job, Garvan::Job'dan türetilmiş bir C++ sınıfıdır. Doğrudan, bir event listener'dan veya admin HTTP API üzerinden (kalpasan job:dispatch'in dahili olarak yaptığı budur) tetiklenebilirler.

Job API

Dört şeyi override edip bir statik factory sağlayın:

// app/jobs/MyJob.h
#include "queue/Job.h"
#include "tools/JsonValue.h"

namespace AppJobs {

class MyJob : public Garvan::Job
{
public:
    MyJob() = default;
    MyJob(std::string arg) : arg_(std::move(arg)) {}

    void handle() override;                                 // işi yapar
    std::string jobName() const override { return "MyJob"; }
    std::string connection() const override { return "sync"; } // sync | async | database

    Garvan::JsonValue payload() const override;             // kalıcı kuyruklar için serileştir
    static std::unique_ptr<Garvan::Job>
        fromPayload(const Garvan::JsonValue& p);            // payload()'un tersi

private:
    std::string arg_;
};

} // namespace AppJobs

Bir job kaydetme

Her user job'ı JobServiceProvider::register_() içinde kaydedin. jobName()'den gelen kısa isimle JobRegistry::bind()'i doğrudan kullanın:

// app/providers/JobServiceProvider.cpp
Garvan::JobRegistry::bind("MyJob", &AppJobs::MyJob::fromPayload);
User job'lar için GARVAN_REGISTER_JOB kullanmayın

GARVAN_REGISTER_JOB(AppJobs::MyJob) macro'su tüm token'i stringify eder ve anahtarı "AppJobs::MyJob" olarak kaydeder, bu da jobName() veya kalpasan job:dispatch'in beklediği kısa isimle eşleşmez. Düzeltmeye bakın: app/providers/JobServiceProvider.cpp:18.

Dispatch

Kodun herhangi bir yerinde — controller, listener veya başka bir job:

#include "queue/JobDispatcher.h"
#include "app/jobs/MyJob.h"

Garvan::JobDispatcher::dispatch(std::make_unique<AppJobs::MyJob>("hello"));

Dispatcher, job'u job->connection() tarafından belirtilen driver'a yönlendirir. Driver'lar service provider'lar tarafından bağlanır; starter'da bugün sadece "sync" bağlı.

SyncDriver

SyncDriver job'u çağıran thread içinde inline çalıştırır. Bu Phase A'daki default'tur ve normal bir fonksiyon çağrısı gibi çağır-ve-dön semantiği verir — testler, düşük throughput görevler veya bir HTTP isteği tarafından tetiklenen pipeline'lar için mükemmel. Async ve database tabanlı driver'lar sonraki fazlarda job sınıflarınızda değişiklik yapmadan aynı JobDispatcher API'sine oturacak.

Örnek: SendTestMail

Paketle gelen AppJobs::SendTestMail (app/jobs/SendTestMail.h:21) gerçek, gönderilebilir bir job'tur. handle()'ı libcurl ile bir SMTP oturumu açar, .env'deki MAIL_* bloğunu kullanarak bir HTML email gönderir ve sonucu stdout'a loglar. SMTP tarafı için Mail (SMTP)'a ve job:dispatch verb'ü için Kalpasan CLI'a bakın.
