Events & Jobs — adım adım

Bu kılavuz sizi tek bir HTTP isteğinden gerçek bir HTML email'in inbox'ınıza gelmesine götürür. Starter'daki event / job pipeline'ının her katmanını çalıştırır — event dispatcher, listener chain, job dispatcher, sync driver ve libcurl SMTP taşıması.

Tam akış

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(AppEvents::UserRegistered)
      → LogRegistrationListener::handle()      (log satırı yazar)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (bu HTTP thread'inde inline)
                     → SendTestMail::handle()  (libcurl SMTP send)

Phase A'da hiçbir şey background worker'a kuyruklanmaz — her adım istek thread'inde çalışır ve HTTP yanıtı ancak mail SMTP sunucusuna teslim edildikten sonra döner. Yani: HTTP 200 aldıysanız, mail sunucu tarafından kabul edildi; reddedildiyse istek server log'unda görünen hatayla biter.

curl ile tetikleme

./bin/app.bin çalışırken ve MAIL_* yapılandırılmışken (bkz. E-posta (SMTP)):

curl "http://localhost:9090/api/events/user-registered?email=you@x.com&name=You&id=1"

Beklenen yanıt:

{
  "status": "fired",
  "event": "UserRegistered",
  "listeners": 2,
  "payload": {"user_id": 1, "email": "you@x.com", "name": "You"}
}

Server log'unu okuma

./bin/app.bin'in çalıştığı terminalde sırayla şunu görmelisiniz:

[LogRegistrationListener] user #1 You <you@x.com> registered
[SendTestMail] dispatch driver=smtp host=smtp.example.com:465 enc=tls from=<...> -> to=<you@x.com> subject="Welcome ..." body_len=...
[SendTestMail] SMTP send OK via smtps://smtp.example.com:465 -> <you@x.com>
(YYYY-MM-DD HH:MM:SS) [INFO    ] Response: ... /api/events/user-registered?... 200 0

Bunun yerine SMTP send FAILED görürseniz, son satır libcurl error string'ini içerir — actionable mesaj odur.

Sorun giderme

  • JSON yerine 404 HTML — çalışan binary'de route'lar kayıtlı değil. ./make.sh ile rebuild ve restart.
  • 404 JSON "no factory for '...'" — URL / payload'daki job veya event adı hiçbir kayıtlı girişle eşleşmiyor. ./kalpasan job:list ve ./kalpasan event:list ile neyin bound olduğunu görün; app/providers/JobServiceProvider.cpp ve EventServiceProvider.cpp'yi kontrol edin.
  • SMTP send OK ama mail inbox'ta yok — önce spam klasörünü kontrol edin. Boşsa, app/jobs/SendTestMail.cpp'de CURLOPT_VERBOSE=1L'yi açın, rebuild, tekrar deneyin ve tam SMTP diyaloğunu okuyun (detaylar).
  • Sessiz takılma — SMTP sunucusu muhtemelen yanıt vermiyor. Aynı makineden openssl s_client -connect <host>:465 deneyin; başarısız olursa ağ / firewall.
  • SPF / DKIM sorunları — yeni bir domain'den gmail.com, abv.bg vs.'ye ilk mail sık sık spam'e filtrelenir. Domain'iniz için SPF / DKIM / DMARC yapılandırın.
