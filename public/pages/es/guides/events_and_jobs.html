Events & Jobs — recorrido

Esta guía te lleva desde una única petición HTTP hasta un email HTML real en tu inbox. Ejercita cada capa del pipeline de event / job en el starter — event dispatcher, listener chain, job dispatcher, sync driver y transporte SMTP con libcurl.

El flujo completo

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(AppEvents::UserRegistered)
      → LogRegistrationListener::handle()      (escribe línea de log)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline en este hilo HTTP)
                     → SendTestMail::handle()  (libcurl SMTP send)

En Phase A nada se encola en un worker en background — cada paso corre en el hilo del request y la respuesta HTTP solo vuelve una vez que el email ha sido entregado al servidor SMTP. Es decir: si obtienes HTTP 200, el mail fue aceptado por el mail server; si fue rechazado, la petición termina con el error visible en el server log.

Trigger con curl

Con ./bin/app.bin corriendo y MAIL_* configurado (ver Correo (SMTP)):

curl "http://localhost:9090/api/events/user-registered?email=you@x.com&name=You&id=1"

Respuesta esperada:

{
  "status": "fired",
  "event": "UserRegistered",
  "listeners": 2,
  "payload": {"user_id": 1, "email": "you@x.com", "name": "You"}
}

Leer el server log

En el terminal donde corre ./bin/app.bin deberías ver, en orden:

[LogRegistrationListener] user #1 You <you@x.com> registered
[SendTestMail] dispatch driver=smtp host=smtp.example.com:465 enc=tls from=<...> -> to=<you@x.com> subject="Welcome ..." body_len=...
[SendTestMail] SMTP send OK via smtps://smtp.example.com:465 -> <you@x.com>
(YYYY-MM-DD HH:MM:SS) [INFO    ] Response: ... /api/events/user-registered?... 200 0

Si ves SMTP send FAILED, la última línea contiene la cadena de error de libcurl — ese es el mensaje accionable.

Resolución de problemas

  • 404 HTML en vez de JSON — el binary corriendo no tiene las rutas registradas. Rebuild con ./make.sh y restart.
  • 404 JSON "no factory for '...'" — el nombre del job o event en la URL / payload no coincide con ninguna entrada registrada. Usa ./kalpasan job:list y ./kalpasan event:list para ver qué está bound; revisa app/providers/JobServiceProvider.cpp y EventServiceProvider.cpp.
  • SMTP send OK pero el mail no llega — primero comprueba el spam folder. Si está vacío, activa CURLOPT_VERBOSE=1L en app/jobs/SendTestMail.cpp, rebuild, retry y lee el diálogo SMTP completo (detalles).
  • Cuelgue silencioso — probablemente el SMTP server no responde. Prueba openssl s_client -connect <host>:465 desde la misma máquina; si falla, red / firewall.
  • Problemas de SPF / DKIM — el primer mail desde un domain nuevo hacia gmail.com, abv.bg, etc. suele filtrarse como spam. Configura SPF / DKIM / DMARC para tu domain.
