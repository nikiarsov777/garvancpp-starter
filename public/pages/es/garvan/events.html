Eventos

Los eventos permiten que una parte de tu app notifique a otras sin saber quién está escuchando. Fire un evento una vez; cada listener registrado se ejecuta — sincronamente, en orden de registro, en el mismo hilo.

Event API

Un evento es una pequeña clase value que hereda de Garvan::Event:

// app/events/UserRegistered.h
#include "events/Event.h"
#include "tools/JsonValue.h"

namespace AppEvents {

class UserRegistered : public Garvan::Event
{
public:
    UserRegistered() = default;
    UserRegistered(int id, std::string mail, std::string person)
        : user_id(id), email(std::move(mail)), name(std::move(person)) {}

    std::string eventName() const override { return "UserRegistered"; }

    Garvan::JsonValue payload() const override;
    static std::unique_ptr<Garvan::Event>
        fromPayload(const Garvan::JsonValue& p);

    int         user_id{};
    std::string email;
    std::string name;
};

} // namespace AppEvents

Escribir un listener

Hereda de Garvan::Listener<YourEvent> e implementa handle():

// app/listeners/SendWelcomeEmailListener.h
#include "events/Listener.h"
#include "../events/UserRegistered.h"

class SendWelcomeEmailListener
    : public Garvan::Listener<AppEvents::UserRegistered>
{
public:
    void handle(const AppEvents::UserRegistered& event) override;
};

El cuerpo del listener puede hacer cualquier cosa — escribir en la base de datos, llamar a un servicio o dispatch un job (que es exactamente lo que hace SendWelcomeEmailListener, reenviando a AppJobs::SendTestMail).

Fire de eventos

#include "events/EventDispatcher.h"
#include "app/events/UserRegistered.h"

Garvan::EventDispatcher::fire(
    std::make_unique<AppEvents::UserRegistered>(42, "u@x.com", "Ada"));

Los listeners se llaman sincronamente en el mismo hilo; si uno lanza excepción, los siguientes se ejecutan igualmente y fire() re-lanza la primera excepción al final.

Registrar en un service provider

Dos registros en EventServiceProvider::register_():

// app/providers/EventServiceProvider.cpp
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                LogRegistrationListener>();
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                SendWelcomeEmailListener>();

// Opcional: registra la factory del evento para el admin API `event:fire`
GARVAN_REGISTER_EVENT(AppEvents::UserRegistered);

A diferencia de GARVAN_REGISTER_JOB, la macro de event está bien: la clave de dispatch se toma de eventName() en runtime, no del nombre stringified del tipo.

Los providers arrancan en main.cpp:56-60 en orden fijo — AppServiceProvider primero (queue drivers), luego JobServiceProvider, después EventServiceProvider. Los listeners pueden dispatch jobs con seguridad en el boot porque los jobs ya están registrados.

Ejemplo: UserRegistered chain

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(UserRegistered)
      → LogRegistrationListener::handle()      (línea de log sync)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline)
                     → SendTestMail::handle()  (libcurl SMTP send)
