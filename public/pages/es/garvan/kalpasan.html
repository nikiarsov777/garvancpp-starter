Kalpasan CLI

kalpasan es el compañero de línea de comandos del proyecto. Scaffold-ea modelos, controllers y services, ejecuta migraciones y seeders, e inicia un servidor de desarrollo con file watching.

Instalación

El binary vive en vendors/Garvan/kalpasan. Un symlink en la raíz del proyecto hace conveniente su llamada:

ln -s vendors/Garvan/kalpasan kalpasan
./kalpasan --help

Scaffolding y comandos de BD

./kalpasan make:model User           # scaffold app/models/User.{h,cpp}
./kalpasan make:controller User      # scaffold app/controllers/UserController.{h,cpp}
./kalpasan make:service User         # scaffold app/services/UserService.{h,cpp}
./kalpasan make:migration create_users

./kalpasan db:migrate                # delega a garvan-migrate up
./kalpasan db:rollback               # delega a garvan-migrate down
./kalpasan db:seed                   # ejecuta archivos en db/seeders/

./kalpasan serve --watch             # rebuild + restart al cambiar .cpp/.h

Todos los comandos respetan el .env activo, así que apuntan a la BD correcta.

Runtime verbs (jobs, events, config)

Estos verbs hablan con una app corriendo vía HTTP (libcurl). Leen KALPASAN_ADMIN_URL (default http://127.0.0.1:9090) y KALPASAN_ADMIN_TOKEN de .env, luego pegan los endpoints admin bearer-guarded en routes/AdminRoute.cpp.

./kalpasan job:list                                # GET /api/admin/jobs
./kalpasan job:dispatch SendTestMail \              # POST /api/admin/jobs/dispatch
    --field to=you@x.com \
    --field subject="Hi" \
    --field body="<h1>Hello</h1>"

./kalpasan event:list                              # GET /api/admin/events
./kalpasan event:fire UserRegistered \             # POST /api/admin/events/fire
    --field id=42 \
    --field email=you@x.com \
    --field name="Ada"

./kalpasan route:list                              # imprime HTTP routes
./kalpasan config:show                             # dump .env
./kalpasan config:get MAIL_HOST                    # lee una clave
./kalpasan config:set MAIL_HOST smtp.new.com       # reescribe una clave
./kalpasan config:key:generate                     # nuevo APP_KEY (base64 32-byte)
Admin auth guard

AdminRoute rechaza la petición si no se cumplen tres condiciones: KALPASAN_ADMIN_TOKEN no vacío en .env, la petición viene de loopback (127.0.0.1 o ::1), y el header Authorization: Bearer <token> coincide. De lo contrario devuelve un JSON error con estado 401 / 403 / 503 (ver routes/AdminRoute.cpp:55-82).
