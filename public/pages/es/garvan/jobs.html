Jobs

Los jobs son unidades de trabajo en segundo plano. Cada job es una clase C++ que hereda de Garvan::Job. Pueden activarse directamente, desde un event listener, o vía la admin HTTP API (que es lo que hace kalpasan job:dispatch internamente).

Job API

Sobrescribe cuatro cosas y proporciona una factory estática:

// app/jobs/MyJob.h
#include "queue/Job.h"
#include "tools/JsonValue.h"

namespace AppJobs {

class MyJob : public Garvan::Job
{
public:
    MyJob() = default;
    MyJob(std::string arg) : arg_(std::move(arg)) {}

    void handle() override;                                 // hace el trabajo
    std::string jobName() const override { return "MyJob"; }
    std::string connection() const override { return "sync"; } // sync | async | database

    Garvan::JsonValue payload() const override;             // serializa para colas persistentes
    static std::unique_ptr<Garvan::Job>
        fromPayload(const Garvan::JsonValue& p);            // inverso de payload()

private:
    std::string arg_;
};

} // namespace AppJobs

Registrar un job

Registra cada user job en JobServiceProvider::register_(). Usa JobRegistry::bind() directamente con el nombre corto de jobName():

// app/providers/JobServiceProvider.cpp
Garvan::JobRegistry::bind("MyJob", &AppJobs::MyJob::fromPayload);
No uses GARVAN_REGISTER_JOB para user jobs

La macro GARVAN_REGISTER_JOB(AppJobs::MyJob) convierte todo el token a string y registra la clave como "AppJobs::MyJob", que luego no coincide con jobName() ni con el nombre corto que espera kalpasan job:dispatch. Ver la corrección en app/providers/JobServiceProvider.cpp:18.

Dispatching

Desde cualquier lugar del código — controller, listener u otro job:

#include "queue/JobDispatcher.h"
#include "app/jobs/MyJob.h"

Garvan::JobDispatcher::dispatch(std::make_unique<AppJobs::MyJob>("hello"));

El dispatcher enruta el job al driver indicado por job->connection(). Los drivers se registran mediante service providers; hoy solo "sync" está conectado en el starter.

SyncDriver

SyncDriver ejecuta el job inline en el hilo que lo llama. Es el default en Phase A y da la misma semántica de llamada-y-retorno que una función normal — perfecto para pruebas, tareas de baja frecuencia o pipelines disparados por una petición HTTP. Los drivers async y basados en base de datos encajarán en la misma API de JobDispatcher en fases posteriores sin cambios en tus clases de job.

Ejemplo: SendTestMail

El AppJobs::SendTestMail incluido (app/jobs/SendTestMail.h:21) es un job real y enviable. Su handle() abre una sesión SMTP con libcurl, envía un email HTML usando el bloque MAIL_* de .env y registra el resultado en stdout. Ver Mail (SMTP) para la parte SMTP y Kalpasan CLI para el verb job:dispatch.
