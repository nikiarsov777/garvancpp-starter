Migraciones

Garvan trae una herramienta de migraciones independiente llamada garvan-migrate. Lee archivos SQL o JSON de db/migrations/, los aplica en orden de versión y registra lo que ya se ha corrido en una tabla de tracking.

Ejecutar migraciones

./vendors/Garvan/garvan-migrate up        # aplica migraciones pendientes
./vendors/Garvan/garvan-migrate down      # revierte la última migración aplicada
./vendors/Garvan/garvan-migrate status    # muestra qué está pendiente / aplicado

La herramienta lee su configuración de conexión del mismo .env que tu app.

Escribir una migración

Los nombres de archivo siguen <UTC YYYYMMDDhhmmss>_<description>.sql. Cada archivo tiene dos secciones, marcadas estilo dbmate:

-- migrate:up
CREATE TABLE posts (
    id          serial PRIMARY KEY,
    title       text NOT NULL,
    body        text,
    user_id     integer REFERENCES users(id),
    created_at  timestamp DEFAULT now()
);

-- migrate:down
DROP TABLE posts;

Para variantes por backend añade .<dbtype> antes de .sql — por ejemplo 20240501_create_posts.mysql.sql.

Rollback

Cada up debe tener un down correspondiente — la herramienta rechaza aplicar una migración sin él. garvan-migrate down las corre en orden inverso, una a la vez.

MongoDB

Para migraciones MongoDB el cuerpo del archivo son uno o más documentos JSON de nivel superior. Cada uno se envía a db.runCommand() en orden.
