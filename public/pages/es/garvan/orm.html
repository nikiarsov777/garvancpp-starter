ORM / Query Builder

La capa de datos de Garvan tiene dos piezas. Builder genera statements parametrizados a través de un Grammar por base de datos, y luego los ejecuta a través de un DbClient. OModel es la clase base que tus objetos modelo extienden para exponer esos métodos del builder directamente.

Builder

El builder usa una API fluida. Cada llamada devuelve el builder para que puedas encadenar condiciones:

Builder qb(dbClient, grammar, "users",
           /*public*/{"id","name","email"},
           /*private*/{"password"});

auto rows = qb
    .where("active", "=", "1")
    ->where("role", "=", "admin")
    ->get();

La consulta está parametrizada de extremo a extremo — los valores suministrados por el usuario fluyen por binding nativo de PreparedStatement en lugar de concatenación de strings. SQL injection no es una opción.

Otros shortcuts: first(), firstOrFail(), find(id), findOrFail(id), más insert(json), update(json) y remove().

OModel

Los modelos extienden ORM::OModel y declaran su nombre de tabla y listas de columnas:

class User : public ORM::OModel
{
public:
    User() {
        table          = "users";
        primaryKey     = "id";
        public_columns  = {"id", "name", "email"};
        private_columns = {"password"};
    }
};

Grammars por base de datos

Cada driver proporciona una subclase Grammar que sabe cómo emitir el dialecto correcto:

  • PostgresGrammar
  • MysqlGrammar
  • SqliteGrammar
  • MonetdbGrammar
  • MongoGrammar — produce comandos Mongo en vez de SQL.

El grammar correcto se elige automáticamente a partir de DATABASE_TYPE. Normalmente no tocarás estas clases directamente.
