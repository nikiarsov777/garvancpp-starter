Eventos

Os eventos permitem que uma parte da sua app notifique outras sem saber quem está a ouvir. Fire um evento uma vez; cada listener registado é executado — sincronamente, por ordem de registo, no mesmo thread.

Event API

Um evento é uma pequena classe value que herda de Garvan::Event:

// app/events/UserRegistered.h
#include "events/Event.h"
#include "tools/JsonValue.h"

namespace AppEvents {

class UserRegistered : public Garvan::Event
{
public:
    UserRegistered() = default;
    UserRegistered(int id, std::string mail, std::string person)
        : user_id(id), email(std::move(mail)), name(std::move(person)) {}

    std::string eventName() const override { return "UserRegistered"; }

    Garvan::JsonValue payload() const override;
    static std::unique_ptr<Garvan::Event>
        fromPayload(const Garvan::JsonValue& p);

    int         user_id{};
    std::string email;
    std::string name;
};

} // namespace AppEvents

Escrever um listener

Herde de Garvan::Listener<YourEvent> e implemente handle():

// app/listeners/SendWelcomeEmailListener.h
#include "events/Listener.h"
#include "../events/UserRegistered.h"

class SendWelcomeEmailListener
    : public Garvan::Listener<AppEvents::UserRegistered>
{
public:
    void handle(const AppEvents::UserRegistered& event) override;
};

O corpo do listener pode fazer qualquer coisa — escrever na base de dados, chamar um serviço ou dispatch um job (que é exatamente o que SendWelcomeEmailListener faz, encaminhando para AppJobs::SendTestMail).

Fire de eventos

#include "events/EventDispatcher.h"
#include "app/events/UserRegistered.h"

Garvan::EventDispatcher::fire(
    std::make_unique<AppEvents::UserRegistered>(42, "u@x.com", "Ada"));

Os listeners são chamados sincronamente no mesmo thread; se um lançar exceção, os seguintes ainda executam e fire() relança a primeira exceção no fim.

Registar num service provider

Dois registos em EventServiceProvider::register_():

// app/providers/EventServiceProvider.cpp
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                LogRegistrationListener>();
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                SendWelcomeEmailListener>();

// Opcional: regista a factory do evento para o admin API `event:fire`
GARVAN_REGISTER_EVENT(AppEvents::UserRegistered);

Ao contrário de GARVAN_REGISTER_JOB, a macro de event está OK: a chave de dispatch vem de eventName() em runtime, não do nome stringified do tipo.

Os providers arrancam em main.cpp:56-60 por ordem fixa — AppServiceProvider primeiro (queue drivers), depois JobServiceProvider, depois EventServiceProvider. Os listeners podem dispatch jobs com segurança no boot porque os jobs já estão registados.

Exemplo: UserRegistered chain

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(UserRegistered)
      → LogRegistrationListener::handle()      (linha de log sync)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline)
                     → SendTestMail::handle()  (libcurl SMTP send)
