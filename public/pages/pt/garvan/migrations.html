Migrações

Garvan traz uma ferramenta de migração independente chamada garvan-migrate. Lê ficheiros SQL ou JSON de db/migrations/, aplica-os por ordem de versão e regista o que já foi corrido numa tabela de tracking.

Correr migrações

./vendors/Garvan/garvan-migrate up        # aplica migrações pendentes
./vendors/Garvan/garvan-migrate down      # reverte a última migração aplicada
./vendors/Garvan/garvan-migrate status    # mostra o que está pendente / aplicado

A ferramenta lê as suas definições de ligação do mesmo .env que a sua app usa.

Escrever uma migração

Os nomes de ficheiro seguem <UTC YYYYMMDDhhmmss>_<description>.sql. Cada ficheiro tem duas secções, marcadas estilo dbmate:

-- migrate:up
CREATE TABLE posts (
    id          serial PRIMARY KEY,
    title       text NOT NULL,
    body        text,
    user_id     integer REFERENCES users(id),
    created_at  timestamp DEFAULT now()
);

-- migrate:down
DROP TABLE posts;

Para variantes por backend acrescente .<dbtype> antes de .sql — por exemplo 20240501_create_posts.mysql.sql.

Rollback

Cada up deve ter um down correspondente — a ferramenta recusa aplicar uma migração sem ele. garvan-migrate down corre-as em ordem inversa, uma de cada vez.

MongoDB

Para migrações MongoDB o corpo do ficheiro são um ou mais documentos JSON de topo. Cada um é enviado a db.runCommand() por ordem.
