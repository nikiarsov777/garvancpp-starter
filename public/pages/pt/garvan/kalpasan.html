Kalpasan CLI

kalpasan é o companheiro de linha de comandos do projeto. Faz scaffold de modelos, controllers e services, corre migrações e seeders, e inicia um servidor de desenvolvimento com file watching.

Instalação

O binary vive em vendors/Garvan/kalpasan. Um symlink na raiz do projeto torna a sua chamada conveniente:

ln -s vendors/Garvan/kalpasan kalpasan
./kalpasan --help

Scaffolding e comandos de BD

./kalpasan make:model User           # scaffold app/models/User.{h,cpp}
./kalpasan make:controller User      # scaffold app/controllers/UserController.{h,cpp}
./kalpasan make:service User         # scaffold app/services/UserService.{h,cpp}
./kalpasan make:migration create_users

./kalpasan db:migrate                # delega para garvan-migrate up
./kalpasan db:rollback               # delega para garvan-migrate down
./kalpasan db:seed                   # corre ficheiros em db/seeders/

./kalpasan serve --watch             # rebuild + restart em mudanças .cpp/.h

Todos os comandos respeitam o .env ativo, portanto apontam para a BD correta.

Runtime verbs (jobs, events, config)

Estes verbs falam com uma app a correr via HTTP (libcurl). Lêem KALPASAN_ADMIN_URL (default http://127.0.0.1:9090) e KALPASAN_ADMIN_TOKEN de .env, depois batem nos endpoints admin bearer-guarded em routes/AdminRoute.cpp.

./kalpasan job:list                                # GET /api/admin/jobs
./kalpasan job:dispatch SendTestMail \              # POST /api/admin/jobs/dispatch
    --field to=you@x.com \
    --field subject="Hi" \
    --field body="<h1>Hello</h1>"

./kalpasan event:list                              # GET /api/admin/events
./kalpasan event:fire UserRegistered \             # POST /api/admin/events/fire
    --field id=42 \
    --field email=you@x.com \
    --field name="Ada"

./kalpasan route:list                              # imprime rotas HTTP
./kalpasan config:show                             # dump .env
./kalpasan config:get MAIL_HOST                    # lê uma chave
./kalpasan config:set MAIL_HOST smtp.new.com       # reescreve uma chave
./kalpasan config:key:generate                     # novo APP_KEY (base64 32-byte)
Admin auth guard

AdminRoute recusa o pedido a menos que três condições se verifiquem: KALPASAN_ADMIN_TOKEN não vazio em .env, o pedido vem de loopback (127.0.0.1 ou ::1), e o header Authorization: Bearer <token> corresponde. Caso contrário devolve JSON error com estado 401 / 403 / 503 (ver routes/AdminRoute.cpp:55-82).
