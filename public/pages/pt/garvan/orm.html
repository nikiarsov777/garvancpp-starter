ORM / Query Builder

A camada de dados do Garvan tem duas peças. Builder gera statements parametrizados através de um Grammar por base de dados, depois corre-os através de um DbClient. OModel é a classe base que os seus objetos modelo estendem para expor esses métodos do builder diretamente.

Builder

O builder usa uma API fluente. Cada chamada devolve o builder para que possa encadear condições:

Builder qb(dbClient, grammar, "users",
           /*public*/{"id","name","email"},
           /*private*/{"password"});

auto rows = qb
    .where("active", "=", "1")
    ->where("role", "=", "admin")
    ->get();

A consulta é parametrizada de ponta a ponta — valores fornecidos pelo utilizador fluem por binding nativo de PreparedStatement em vez de concatenação de strings. SQL injection não está em cima da mesa.

Outros shortcuts: first(), firstOrFail(), find(id), findOrFail(id), mais insert(json), update(json) e remove().

OModel

Os modelos estendem ORM::OModel e declaram o seu nome de tabela e listas de colunas:

class User : public ORM::OModel
{
public:
    User() {
        table          = "users";
        primaryKey     = "id";
        public_columns  = {"id", "name", "email"};
        private_columns = {"password"};
    }
};

Grammars por base de dados

Cada driver fornece uma subclasse Grammar que sabe como emitir o dialeto correto:

  • PostgresGrammar
  • MysqlGrammar
  • SqliteGrammar
  • MonetdbGrammar
  • MongoGrammar — produz comandos Mongo em vez de SQL.

O grammar correto é escolhido automaticamente a partir de DATABASE_TYPE. Normalmente não vai tocar nestas classes diretamente.
