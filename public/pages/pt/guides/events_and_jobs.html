Events & Jobs — passo a passo

Este guia leva-o de um único pedido HTTP até um email HTML real na sua inbox. Exercita cada camada do pipeline de event / job no starter — event dispatcher, listener chain, job dispatcher, sync driver e transporte SMTP via libcurl.

O fluxo completo

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(AppEvents::UserRegistered)
      → LogRegistrationListener::handle()      (escreve linha de log)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline neste thread HTTP)
                     → SendTestMail::handle()  (libcurl SMTP send)

Em Phase A nada é enfileirado num worker em background — cada passo corre no thread do request e a resposta HTTP só volta quando o email foi entregue ao servidor SMTP. Ou seja: se receber HTTP 200, o mail foi aceite pelo mail server; se foi rejeitado, o pedido acaba com o erro visível no server log.

Trigger com curl

Com ./bin/app.bin a correr e MAIL_* configurado (ver E-mail (SMTP)):

curl "http://localhost:9090/api/events/user-registered?email=you@x.com&name=You&id=1"

Resposta esperada:

{
  "status": "fired",
  "event": "UserRegistered",
  "listeners": 2,
  "payload": {"user_id": 1, "email": "you@x.com", "name": "You"}
}

Ler o server log

No terminal onde ./bin/app.bin corre deverá ver, por ordem:

[LogRegistrationListener] user #1 You <you@x.com> registered
[SendTestMail] dispatch driver=smtp host=smtp.example.com:465 enc=tls from=<...> -> to=<you@x.com> subject="Welcome ..." body_len=...
[SendTestMail] SMTP send OK via smtps://smtp.example.com:465 -> <you@x.com>
(YYYY-MM-DD HH:MM:SS) [INFO    ] Response: ... /api/events/user-registered?... 200 0

Se em vez disso vir SMTP send FAILED, a última linha contém a string de erro do libcurl — essa é a mensagem accionável.

Resolução de problemas

  • 404 HTML em vez de JSON — o binary a correr não tem as rotas registadas. Rebuild com ./make.sh e restart.
  • 404 JSON "no factory for '...'" — o nome do job ou event no URL / payload não corresponde a nenhuma entrada registada. Use ./kalpasan job:list e ./kalpasan event:list para ver o que está bound; verifique app/providers/JobServiceProvider.cpp e EventServiceProvider.cpp.
  • SMTP send OK mas o mail não chega — primeiro verifique a pasta de spam. Se estiver vazia, active CURLOPT_VERBOSE=1L em app/jobs/SendTestMail.cpp, rebuild, retry e leia o diálogo SMTP completo (detalhes).
  • Bloqueio silencioso — o servidor SMTP provavelmente não responde. Experimente openssl s_client -connect <host>:465 da mesma máquina; se falhar, rede / firewall.
  • Problemas de SPF / DKIM — o primeiro mail de um domain novo para gmail.com, abv.bg, etc. é frequentemente filtrado como spam. Configure SPF / DKIM / DMARC para o seu domain.
