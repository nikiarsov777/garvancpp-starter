Jobs

Jobs — это единицы фоновой работы. Каждый job является C++ классом, наследующим Garvan::Job. Их можно запускать напрямую, из event listener или через admin HTTP API (именно так работает kalpasan job:dispatch внутри).

Job API

Переопределите четыре метода и предоставьте одну статическую фабрику:

// app/jobs/MyJob.h
#include "queue/Job.h"
#include "tools/JsonValue.h"

namespace AppJobs {

class MyJob : public Garvan::Job
{
public:
    MyJob() = default;
    MyJob(std::string arg) : arg_(std::move(arg)) {}

    void handle() override;                                 // выполняет работу
    std::string jobName() const override { return "MyJob"; }
    std::string connection() const override { return "sync"; } // sync | async | database

    Garvan::JsonValue payload() const override;             // сериализация для persistent queue
    static std::unique_ptr<Garvan::Job>
        fromPayload(const Garvan::JsonValue& p);            // обратное к payload()

private:
    std::string arg_;
};

} // namespace AppJobs

Регистрация job

Регистрируйте каждый пользовательский job в JobServiceProvider::register_(). Используйте JobRegistry::bind() напрямую с коротким именем из jobName():

// app/providers/JobServiceProvider.cpp
Garvan::JobRegistry::bind("MyJob", &AppJobs::MyJob::fromPayload);
Не используйте GARVAN_REGISTER_JOB для пользовательских jobs

Макрос GARVAN_REGISTER_JOB(AppJobs::MyJob) stringify-ит весь токен и регистрирует ключ как "AppJobs::MyJob", что не совпадает с jobName() или коротким именем, которое ожидает kalpasan job:dispatch. См. исправление в app/providers/JobServiceProvider.cpp:18.

Dispatch

Из любого места кода — controller, listener или другой job:

#include "queue/JobDispatcher.h"
#include "app/jobs/MyJob.h"

Garvan::JobDispatcher::dispatch(std::make_unique<AppJobs::MyJob>("hello"));

Dispatcher маршрутизирует job к драйверу, указанному в job->connection(). Драйверы связываются service provider-ами; в starter сегодня подключён только "sync".

SyncDriver

SyncDriver выполняет job inline в вызывающем потоке. Это default в Phase A и даёт call-and-return семантику как у обычной функции — идеально для тестов, low-throughput задач или pipeline-ов, запускаемых HTTP запросом. Async и database драйверы подключатся к тому же JobDispatcher API в следующих фазах без изменений в ваших job-классах.

Пример: SendTestMail

Встроенный AppJobs::SendTestMail (app/jobs/SendTestMail.h:21) — реальный, отправляющий job. Его handle() открывает SMTP сессию с libcurl, отправляет HTML email используя блок MAIL_* из .env и логирует результат в stdout. См. Mail (SMTP) для SMTP части и Kalpasan CLI для verb job:dispatch.
