Миграции

Garvan поставляет отдельный migration инструмент garvan-migrate. Он читает SQL или JSON файлы из db/migrations/, применяет их в порядке версий и записывает что уже выполнено в tracking таблице.

Запуск миграций

./vendors/Garvan/garvan-migrate up        # применяет pending миграции
./vendors/Garvan/garvan-migrate down      # откатывает последнюю применённую миграцию
./vendors/Garvan/garvan-migrate status    # показывает pending / applied

Инструмент читает настройки подключения из того же .env, что и ваш app.

Написание миграции

Имена файлов следуют <UTC YYYYMMDDhhmmss>_<description>.sql. Каждый файл имеет две секции, помеченные dbmate-стиль:

-- migrate:up
CREATE TABLE posts (
    id          serial PRIMARY KEY,
    title       text NOT NULL,
    body        text,
    user_id     integer REFERENCES users(id),
    created_at  timestamp DEFAULT now()
);

-- migrate:down
DROP TABLE posts;

Для per-backend вариантов добавьте .<dbtype> перед .sql — например 20240501_create_posts.mysql.sql.

Rollback

Каждый up должен иметь соответствующий down — инструмент отказывается применять миграцию без него. garvan-migrate down запускает их в обратном порядке, по одной.

MongoDB

Для MongoDB миграций тело файла — один или больше top-level JSON документов. Каждый отправляется в db.runCommand() по порядку.
