События

События позволяют одной части приложения уведомлять другие, не зная, кто слушает. Fire событие один раз; каждый зарегистрированный listener выполнится — синхронно, в порядке регистрации, в том же потоке.

Event API

Событие — маленький value-класс, наследующий Garvan::Event:

// app/events/UserRegistered.h
#include "events/Event.h"
#include "tools/JsonValue.h"

namespace AppEvents {

class UserRegistered : public Garvan::Event
{
public:
    UserRegistered() = default;
    UserRegistered(int id, std::string mail, std::string person)
        : user_id(id), email(std::move(mail)), name(std::move(person)) {}

    std::string eventName() const override { return "UserRegistered"; }

    Garvan::JsonValue payload() const override;
    static std::unique_ptr<Garvan::Event>
        fromPayload(const Garvan::JsonValue& p);

    int         user_id{};
    std::string email;
    std::string name;
};

} // namespace AppEvents

Написание listener

Наследуйте от Garvan::Listener<YourEvent> и реализуйте handle():

// app/listeners/SendWelcomeEmailListener.h
#include "events/Listener.h"
#include "../events/UserRegistered.h"

class SendWelcomeEmailListener
    : public Garvan::Listener<AppEvents::UserRegistered>
{
public:
    void handle(const AppEvents::UserRegistered& event) override;
};

Тело listener может делать что угодно — писать в БД, вызывать сервис или dispatch-ить job (именно это делает SendWelcomeEmailListener, перенаправляя к AppJobs::SendTestMail).

Fire событий

#include "events/EventDispatcher.h"
#include "app/events/UserRegistered.h"

Garvan::EventDispatcher::fire(
    std::make_unique<AppEvents::UserRegistered>(42, "u@x.com", "Ada"));

Listener-ы вызываются синхронно в том же потоке; если один бросает исключение, последующие всё равно выполняются, а fire() пере-бросит первое исключение в конце.

Регистрация в service provider

Две регистрации в EventServiceProvider::register_():

// app/providers/EventServiceProvider.cpp
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                LogRegistrationListener>();
Garvan::EventDispatcher::listen<AppEvents::UserRegistered,
                                SendWelcomeEmailListener>();

// Опционально: регистрирует factory события для admin API `event:fire`
GARVAN_REGISTER_EVENT(AppEvents::UserRegistered);

В отличие от GARVAN_REGISTER_JOB, event макрос в порядке: dispatch-ключ берётся из eventName() в runtime, а не из stringified имени типа.

Provider-ы boot-ят в main.cpp:56-60 в фиксированном порядке — AppServiceProvider первым (queue drivers), затем JobServiceProvider, затем EventServiceProvider. Listener-ы могут безопасно dispatch-ить jobs при boot, потому что jobs уже зарегистрированы.

Пример: UserRegistered chain

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(UserRegistered)
      → LogRegistrationListener::handle()      (sync log строка)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline)
                     → SendTestMail::handle()  (libcurl SMTP send)
