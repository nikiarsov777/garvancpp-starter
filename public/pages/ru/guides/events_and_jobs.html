Events & Jobs — пошагово

Это руководство ведёт вас от одного HTTP-запроса до реального HTML email в inbox. Проходит через каждый слой event / job pipeline в starter — event dispatcher, listener chain, job dispatcher, sync driver и libcurl SMTP транспорт.

Полный поток

GET /api/events/user-registered?email=...&name=...&id=...
  → EventDispatcher::fire(AppEvents::UserRegistered)
      → LogRegistrationListener::handle()      (пишет log строку)
      → SendWelcomeEmailListener::handle()
           → JobDispatcher::dispatch(SendTestMail)
                → SyncDriver (inline в этом HTTP потоке)
                     → SendTestMail::handle()  (libcurl SMTP send)

В Phase A ничего не queue-ится в background worker — каждый шаг выполняется в потоке запроса и HTTP ответ возвращается только когда email передан SMTP серверу. То есть: если получили HTTP 200, письмо принято mail сервером; если отклонено, запрос заканчивается с ошибкой видимой в server log.

Триггер через curl

С запущенным ./bin/app.bin и настроенным MAIL_* (см. Почта (SMTP)):

curl "http://localhost:9090/api/events/user-registered?email=you@x.com&name=You&id=1"

Ожидаемый response:

{
  "status": "fired",
  "event": "UserRegistered",
  "listeners": 2,
  "payload": {"user_id": 1, "email": "you@x.com", "name": "You"}
}

Чтение server log

В терминале где работает ./bin/app.bin вы должны увидеть по порядку:

[LogRegistrationListener] user #1 You <you@x.com> registered
[SendTestMail] dispatch driver=smtp host=smtp.example.com:465 enc=tls from=<...> -> to=<you@x.com> subject="Welcome ..." body_len=...
[SendTestMail] SMTP send OK via smtps://smtp.example.com:465 -> <you@x.com>
(YYYY-MM-DD HH:MM:SS) [INFO    ] Response: ... /api/events/user-registered?... 200 0

Если видите SMTP send FAILED, последняя строка содержит libcurl error string — это actionable сообщение.

Устранение неполадок

  • 404 HTML вместо JSON — работающий binary не имеет зарегистрированных routes. Rebuild с ./make.sh и restart.
  • 404 JSON "no factory for '...'" — имя job или event в URL / payload не соответствует зарегистрированной записи. Используйте ./kalpasan job:list и ./kalpasan event:list чтобы увидеть что bound; проверьте app/providers/JobServiceProvider.cpp и EventServiceProvider.cpp.
  • SMTP send OK но письма нет в inbox — сначала проверьте spam folder. Если пусто, переключите CURLOPT_VERBOSE=1L в app/jobs/SendTestMail.cpp, rebuild, retry и прочитайте полный SMTP диалог (детали).
  • Тихое зависание — SMTP сервер вероятно не отвечает. Попробуйте openssl s_client -connect <host>:465 с той же машины; если не работает — сеть / firewall.
  • Проблемы с SPF / DKIM — первое письмо со свежего domain на gmail.com, abv.bg и т.д. часто фильтруется как spam. Настройте SPF / DKIM / DMARC для вашего domain.
